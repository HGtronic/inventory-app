Architecture overview

Factory Inventory Management System

A full-stack demo. A Vue 3 single-page app talks over HTTP to a Python FastAPI service, which serves mock factory data loaded from JSON files into memory. There is no database, no authentication, and nothing is written back.

01

System architecture

There are two processes. The browser runs the Vue app from the Vite dev server, and a uvicorn process runs the FastAPI app. The only link between them is client/src/api.js.

Every view, Reports included, reaches the backend through api.js. The backend port is 8001 unless API_PORT / VITE_API_BASE_URL override it.

03

Data flow

Example: on the Inventory page, the user sets the Location filter to Tokyo. The other views and filters follow the same path.

Filters are global singletonsThe four refs in useFilters.js live at module level, so every view reads the same values. Filters are not synced to the URL, and reloads are not debounced.
'all' never leaves the browserapi.js drops any filter set to 'all'. On the server, warehouse is matched exactly, while category and status ignore case.
Month only applies to ordersInventory has no date field. filter_by_month also accepts Q1-2025 to Q4-2025, but the FilterBar only offers single months.
Some joins happen in the browserDashboard, Demand and Backlog narrow down forecasts and backlog by the SKUs in the filtered inventory. Finance fetches everything and filters by period on the client.
Data is loaded onceImporting mock_data.py reads the seven JSON files once. Requests only read the in-memory lists, so changing a JSON file means restarting the server.
Raw refs, derived computedsViews keep API responses in refs (for example allOrders and inventoryItems) and compute KPIs, chart series and sorted tables from them.

07

Things to know

Places where the code differs from the docs or from itself. The items marked Fixed were resolved on 3 Nov 2026 and verified with backend tests and in the browser.

Fixed
Tasks and purchase-order endpoints were missing

main.py now serves /api/tasks (list, create, toggle, delete) and /api/purchase-orders (create, and get by backlog item), with validation and tests in tests/backend/test_tasks_purchase_orders.py.

Fixed
Dashboard used a component that did not exist

components/PurchaseOrderModal.vue now exists, with create and view modes. The Create/View PO buttons switch on has_purchase_order from /api/backlog, so the state survives a page reload.

Fixed
Backend port drift

The port is now configurable and defaults to the documented 8001 everywhere. The backend reads API_PORT, the client reads VITE_API_BASE_URL (see .env.example), and start.sh / stop.sh respect API_PORT. stop.sh now stops only this app's own Python and Node processes, never whatever else holds the port.

Fixed
Reports.vue broke the frontend conventions

It is rewritten with the Composition API and calls api.js. Every string is translated, there is no console logging, and money goes through utils/currency.js.

Fixed
Japanese currency mode was only partly converted

Every money display now goes through utils/currency.js, which converts USD to JPY. Chart axes use the new formatCurrencyCompact, and exact amounts keep fractional yen so that unit price × quantity matches the line total.

Fixed
Mock tasks could not be completed or deleted

App.vue used to change the non-reactive currentUser object directly, so nothing updated on screen. It now keeps those edits in its own state, so they show immediately and survive a language switch. The profile-menu badge counts pending tasks from the same merged list.

Fixed
Dashboard KPIs were hard-coded

/api/dashboard/summary now computes inventory turnover, orders fulfilled (out of all orders), order fill rate and average delivery time from the filtered data. The data has no ship date, so the old "processing time" card now shows delivery time against the promised lead time.

Fixed
Backlog.vue was unreachable

It is now routed at /backlog and linked from the Dashboard's Inventory Shortages card ("View all"). It is translated and shows a "PO placed" badge.

Note
Some data ignores the filters

total_backlog_items in /dashboard/summary always counts every backlog item. Finance ignores warehouse, category and status.
